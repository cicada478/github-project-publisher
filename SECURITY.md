# Security Policy / 安全策略

## 中文

请勿在公开 Issue、讨论、提交信息或 Release Notes 中披露真实凭证、个人信息、支付数据、可利用细节或未脱敏日志。

如果 GitHub 仓库已启用 Private vulnerability reporting，请优先通过该渠道报告。如果尚无私密渠道，可提交一个不包含漏洞细节和敏感数据的最小公开 Issue，请求维护者提供私密联系方式。

若发现真实凭证已经暴露：

1. 立即停止提交和发布；
2. 先撤销或轮换凭证；
3. 保存不含敏感原值的文件位置、提交 SHA 和影响范围；
4. 由仓库所有者决定历史清理、通知和后续发布方案。

## English

Do not disclose live credentials, personal information, payment data, exploitable details, or unredacted logs in public issues, discussions, commit messages, or Release Notes.

Use GitHub Private vulnerability reporting when it is enabled. If no private channel is available, open a minimal public issue that contains no vulnerability detail or sensitive value and ask the maintainer for a private contact method.

If a live credential has been exposed:

1. stop commit and publication operations immediately;
2. revoke or rotate the credential first;
3. preserve only redacted location, commit SHA, and impact evidence;
4. let the repository owner decide history remediation, notification, and republishing.
